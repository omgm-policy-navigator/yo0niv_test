# 기능 요구사항

## MVP 필수 기능

### 1. 정책 분야 선택

서비스는 사용자가 탐색을 시작할 수 있도록 5개 정책 분야를 선제시해야 한다.

- 주거
- 대출
- 웨딩
- 세제
- 출산·육아

### 2. 분야별 질문 흐름

서비스는 선택 분야에 맞는 고정 질문과 조건부 질문을 제공해야 한다.

질문은 다음 속성을 가져야 한다.

- 질문 문구
- 조건 키
- 답변 타입
- 선택지
- 우선순위
- 상위 질문
- 표시 조건

### 3. 사용자 조건 저장

서비스는 사용자의 답변을 자유 텍스트가 아닌 구조화된 조건으로 저장해야 한다.

예시:

```text
condition_key: MARRIAGE_STATUS
value: PRE_MARRIED
```

```text
condition_key: RESIDENCE_REGION
value: SEOUL
```

### 4. 룰베이스 사전진단

서비스는 정책별 자격 조건과 사용자 조건을 비교해 다음 항목을 계산해야 한다.

- 충족 조건
- 미충족 조건
- 미확인 조건
- 추천 점수
- 판정 상태

판정 상태는 다음 값을 사용한다.

```text
LIKELY_ELIGIBLE
NEEDS_CONFIRMATION
AVAILABLE_LATER
LIKELY_INELIGIBLE
OFFICIAL_CONFIRMATION_REQUIRED
```

### 5. 사용자 정책 그래프

서비스는 사용자의 상황을 기준으로 정책 후보와 부족한 조건, 다음 행동을 그래프 형태로 제공해야 한다.

그래프에는 다음 노드가 포함될 수 있다.

- 사용자
- 선택 분야
- 정책 후보
- 충족 조건
- 확인 필요 조건
- 실패 조건
- 다음 행동

### 6. 그래프 연동 챗봇

사용자가 정책, 조건, 행동 노드를 선택하면 챗봇은 해당 노드와 관련된 설명을 제공해야 한다.

챗봇 응답은 다음 정보를 활용해야 한다.

- 사용자 조건
- 정책 판정 결과
- 정책 관계
- 공식 정책 문서
- RAG 검색 결과

### 7. RAG 정책 설명

서비스는 공식 원문을 기반으로 정책 신청 조건, 필요 서류, 신청 절차, 유의사항을 설명해야 한다.

RAG 응답은 공식 출처와 기준일을 함께 제공해야 한다.

### 8. 정책 상세

정책 상세 화면 또는 응답에는 다음 정보를 포함해야 한다.

- 정책명
- 요약
- 관리 기관
- 신청 URL
- 신청 시작일
- 신청 종료일
- 상태
- 공식 출처 URL
- 기준 확인일

## MVP 이후 기능 후보
